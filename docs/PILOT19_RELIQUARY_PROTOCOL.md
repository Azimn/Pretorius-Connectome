# Pilot19 — THE RELIQUARY: Evidence-Bound Episodic Detail Associations

**Preregistered before any Pilot19 metrics were generated.** Experimental owner: Pretorius-Connectome. No edits to existing 450 canonical fictional autobiographical events or their original 450 unreviewed cue sidecars. Distinct from the 139,255-neuron complete FlyWire network: this is **EXPLICIT EXTERNAL provenance-bound episodic retrieval**, not a synaptic/neural learning experiment, semantic paraphrase benchmark, or demonstration of real personal memory.

## Correction driving the intervention

[Pilot18 original source audit](../results/imprinting/PILOT18_ORIGINAL_CUE_SOURCE_AUDIT.md) establishes that the 450 candidate annotation sidecars are **ALL `unreviewed_candidate`**. They contain 1,463 predominantly short details, median 2 words. Of 448 events with three distinct selected cues, 446 have no identical first/last word. A source event might have `turned glove`, `millstream map`, `green tape`: distinct details associated *because they occurred in one episode*, not equivalent sentences. Pilot18's fitted semantic pair-scatter metric retrieved 0/316 held-out last literal anchors when only first/middle cues were available. We no longer use the phrase “paraphrase generalization failure” for that study.

Related designs, not performance validations of our implementation: [EventRAG (ACL 2025)](https://aclanthology.org/2025.acl-long.830/) uses event-graph representations for narrative-rich retrieval; [SEEM (ACL 2026)](https://aclanthology.org/2026.acl-long.277/) uses provenance-linked episode frames; [RippleMem (arXiv 2608.13334)](https://arxiv.org/abs/2608.13334) emphasizes associative recollection of evidence; [EpBench (ICLR 2025)](https://github.com/ahstat/episodic-memory-benchmark) tests event/time/location/entity context; [MAGIC (EMNLP 2025)](https://aclanthology.org/2025.findings-emnlp.466/) studies source-conflict recognition. Their measured scores may NOT be borrowed to support Pretorius.

## Two orthogonal questions, never silently conflated

**Q1. Source availability / event ownership.** Does exposing **existing original event-owned detail annotations** allow a system to route a third cue to its correct source episode? This deliberately changes what information is stored, so even excellent recall tests **previously indexed source detail**, not unseen-semantic generalization. Every recovered item must identify exact source event + field + cue evidence and preserve annotation status. A wrong event's candidate cue is not Pretorius's memory, regardless of its lexical similarity.

**Q2. Retrieval mechanism.** Given identical original source evidence, does an event graph offer any measurable benefit over a flat BM25 document index or direct exact-cue inverted index? A one-hop cue→event→other detail association can be represented equally well by a flat document index; do **not** attribute success to a graph if plain lookup matches. No fabricated relationship strength or “semantic thinking” credit from indexing alone.

The original independent human-written **paraphrase plus fabricated absent-memory** study is a separate later task: no such independently blind expert annotation is currently available. No assistant-written cues will be disguised as that battery.

## Original source, strict split, query/evidence availability

Freeze 450 canonical v12 fictional first-person event narratives/27 episodes, original sidecars and original seed31 episode-isolated **317 train**, **62 validation episode-absent**, **71 test episode-absent**; original chronological/source ordering seed20261008 unchanged. **Only the 317 TRAIN events** may enter ANY index, including participant and location edges, narrative corpus or cue sidecars. Absent episode content/metadata cannot leak into the retrieval index. Training-sidecar fields are unreviewed evidence candidates; preserve exact string, event ID, record source SHA and `annotation_status`, and mark type `candidate_annotation`; raw original memory prose is separately stored with `memory_text` provenance. No original CONTENT codebook, trained numeric W/P or narrative generator in retrieval code. An event ID internally indexes a stored event **by explicit design**. It is not a claim of distributed neural inference.

Freeze as test query set the **third selected source cue** of each TRAIN event with **three distinct selected cues** (Pilot18 observed **316/317** eligible); old 159 trained first literal query cases, original 31 previously explored fourth literal cases (exploratory only), 62 validation-absent last-cue strings and 71 test-absent last-cue strings. Report duplicates and cross-event collisions. These test strings ARE in the original source corpus/annotations and previously examined across Pilots08–18. When an index uses an original sidecar containing third literal, it is **in-index exposure**, not a heldout cue; when it uses narrative text containing last cue, it is **narrative exposure** if verbatim. A first+middle-only index **genuinely withheld** the third annotation.

Six predeclared independent index arms (same candidate events but intentionally DIFFERENT available evidence):

1. `train_two_anchors_only`: first+middle original sidecar cue strings ONLY. *True third cue withheld.* Exact normalized phrase matching, no narrative available.
2. `narrative_bm25`: original full source `memory_text` for 317 train events, no sidecar annotations. May contain third cue literal; classify lexical exposure per case.
3. `all_anchors_flat_bm25`: all original candidate sidecar cue surfaces concatenated into a flat searchable document, including third cue. **Exposure = indexed**, not generalization.
4. `all_anchors_exact_index`: all sidecar cue surfaces in an event-owned exact normalized phrase inverted index. Report ties/ambiguous cue owners. A distinct-index baseline using exactly the same sidecar evidence as the event graph.
5. `reliquary_event_graph`: explicitly represent source event nodes, candidate-detail nodes, `observed-in-annotation` edges and original `participant`/`location` nodes. Query exact candidate-detail cue → event → first cue/other metadata. The primary response is source provenance + retrieved original *other* associated detail, not an inference that two details are synonymous. For this cue-only benchmark it is **expected to equal the exact index**, unless implementation error. Graph is useful for auditable relation structure and future multi-cue exploration, not a free performance claim.
6. `wrong_owner_graph`: same detail strings and same graph storage categories, but permute event ownership by deterministic non-self fixed rotation over train events. **Negative provenance control**; if matches real original IDs as often as true graph, fail the source-ownership hypothesis.

Threshold/rejection: predeclare `score>0` for exact phrase index and any non-empty BM25 lexical match for open-world acceptance; BM25 rankings always exist even for unrelated text, so normalize gating from **62 validation-absent episodes alone** (select threshold with <=6/62 false accepts, no tuning on 71 test negatives or 316 third queries), and report known **correct AND accepted** plus validation/test absent false accepts. For exact/graph, `score=1` only for exact candidate cue evidence and threshold `0` (ties abstain rather than invent a distinct source). Phrase that occurs in two events is intrinsically ambiguous; **abstain rather than choose an arbitrary source**. For BM25, positive lexical overlap can match different episodes; score threshold chosen against validation absences without inspecting 71 test results.

All arms report each case's source record ID, chosen returned ID, correct/accepted, original phrase available in indexed annotations, original phrase verbatim in indexed narrative, matching evidence field/status, resolved ambiguity, source event provenance and a second retrieved associated cue for graph arm. Exactly full per-case JSON and aggregated measured report required.

## Success/failure interpretation gates

**Expected positive but limited:** exact sidecar index and event graph should retrieve many original third cues because those cues are **already indexed**. This establishes source-linked association and the value of preserving event evidence; it is not emergent semantic inference or a neural model's memory. Sidecar wrong-owner control must fail event attribution (negative control). If graph and exact baseline tie, report **no graph-specific effectiveness advantage**; no post-hoc claim of structural causality. True third-withheld first+middle arm might remain at zero; that is an honest missing-evidence finding, not an error.

**Risk:** original source cue annotations are `unreviewed_candidate`; even perfectly retrieving `green tape` from the original sidecar is not evidence that Pretorius *actually experienced* it or that the detail occurs in source prose. Compute source evidence coverage and separate verbatim narrative support from annotation-only candidate detail. Do not convert unreviewed candidate to “verified episodic perception.”

**Future independent gate:** human-reviewed cue relationships and *new* blinded authored paraphrases plus absent memories, false ownership and memory distortion, before promoting this into the character’s synthetic autobiographical state. Direct original narrative indexing must be distinguished from separately trained neural source state, and surface strings cannot be treated as subject's accepted autobiographical memories without separate subject-access boundaries.
